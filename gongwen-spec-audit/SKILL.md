# 公文辅助校验助手（gongwen-spec-audit）

> 中文技能名：**公文辅助校验助手**
> 标准依据：《党政机关公文格式》GB/T 9704—2012、《党政机关公文处理工作条例》

本 Skill 提供**公文辅助校验的三个模块**，全部基于国标规则，本地运行、不联网、不调外部模型。本文件是 AI 调用入口：你（AI 客户端）在用户触发以下任一场景时应加载本 Skill，并按对应模块的工作流程执行。

> **能力边界（重要）**：本 Skill 仅做**辅助校验**（核查已有公文的问题、提取已有公文的要素、校正已有公文的术语）。**不具备**公文起草、红头版式生成、Word/PDF 导出等能力——用户若需这些，应明确告知超出本 Skill 范围。

---

## 一、何时加载本 Skill（能力边界）

当用户的请求命中下面**任一**场景时加载：

| 场景关键词 | 对应模块 |
|-----------|---------|
| "校验/检查/核稿/自查"公文格式、发文字号、成文日期、层次序号、落款、称谓 | 模块① 格式校验 |
| "提取/摘要/登记"来文的发文字号、机关、事由、要求、时限 | 模块② 信息提取 |
| "规范/校正"公文术语、用语、表述 | 模块③ 术语校正 |

**不应加载**的情况（避免跨场景误触发）：
- 用户要"起草/写/生成"一份公文 → 本 Skill **不做起草**，应告知超出能力范围；
- 用户要"导出/生成 Word/PDF/红头"→ 本 Skill **不做版式生成**，应告知超出能力范围；
- 用户只要"翻译/润色一段普通文字"（非公文）→ 不加载。

## 二、三个模块的标准工作流程（SOP）

### 模块①：格式合规校验

**输入**：用户给出的公文文本（粘贴或文件路径）。
**输出**：Markdown 校验报告，按 🔴严重 / 🟡提醒 / 🟢建议 分级，每条含「问题位置 + 标准依据 + 修改示例」。

执行步骤：
1. 读取公文全文（用户粘贴则直接用；给路径则用脚本读取）。
2. **结构分析**：识别版头、标题、主送机关、正文、落款、版记各部分；识别正文层次序号（一、(一)、1.、(1)）。
3. **规则校验**：参照 `references/gbt9704-2012-spec.md`，逐项检查：
   - 发文字号：是否「机关代字〔年份〕顺序号」、年份是否用六角括号〔〕、顺序号是否不加"第"不编虚位；
   - 成文日期：是否用阿拉伯数字、年月日是否标全、月日是否不编虚位；
   - 层次序号：是否「一、(一)、1.、(1)」逐级、有无跳级或混用、第二层是否误用半角括号；
   - 主送机关（称谓）：是否顶格、末尾是否全角冒号；
   - 标题：是否含「发文机关 + 事由 + 文种」三要素；
   - 要素完整性：密级/紧急程度/签发人（上行文）/抄送末尾句号等；
   - 标点符号：全角半角混用、附件说明末尾是否多标点。
4. **生成报告**：机器可判定的项优先调用 `scripts/gongwen_toolkit.py check` 得到确定结论；语义判断的项由 AI 基于上下文给出建议并标注「建议复核」。
5. 调用脚本命令：`python scripts/gongwen_toolkit.py check <文件路径>`（纯标准库，无需装任何库）。

**AI 与脚本的分工**：
- **脚本负责机器可判定的硬规则**（发文字号正则、成文日期数字、层次序号格式、要素是否存在）→ 结论为"确定"；
- **AI 负责语义级判断**（标题事由是否贴切、文种是否恰当、主送机关是否合适）→ 结论为"建议复核"；
- 两者结果合并输出，不重复、不矛盾。

### 模块②：关键信息提取

**输入**：一份来文文本。
**输出**：结构化要素表（Markdown 表格），可用于收文登记/拟办参考。

提取要素：发文字号、发文机关、成文日期、关键数据（金额/数量等）、时限要求。
调用脚本：`python scripts/gongwen_toolkit.py extract <文件路径>`（机器抽取模式化字段；事由、核心要求等语义字段由 AI 补充）。

### 模块③：规范术语校正

**输入**：公文文本。
**输出**：逐条「原句 → 规范表述 → 依据」。

执行步骤：
1. 加载 `references/gongwen-glossary.md` 术语对照表。
2. 扫描文本中不规范用语（文种混用、过时套语、量词/日期表述不规范、口语化表述等）。
3. 给出规范替换建议与依据。
4. 调用脚本：`python scripts/gongwen_toolkit.py glossary <文件路径>`。

## 三、输入输出约定

- **输入**：优先接受用户粘贴的公文纯文本；若用户给文件路径，用脚本读取（`.txt`/`.md`，或由用户先转成纯文本）。
- **输出**：一律用 Markdown；表格中动态字段已做转义（脚本内 `sanitize_cell`）。
- **语言**：中文，术语遵循国标，不夹英文除非引用标准编号（如 GB/T 9704）。

---

## 四、结果验收标准

- 模块①：对含 3 类典型错误的样例（`samples/校验-含错.txt`）应报出 ≥3 个问题；对合规样例（`samples/校验-合规.txt`）应报 0 个严重问题。
- 模块②：对样例来文应准确抽出 ≥3 个要素。
- 模块③：对含不规范用语的文本应识别并给出规范改法。

测试命令：`python tests/run_test.py`。

---

## 五、不应该做什么（边界与合规）

1. **不起草公文**：不生成公文草稿、不填充公文骨架、不补全正文内容（仅核查已有公文）。
2. **不生成版式文件**：不生成 Word/PDF、不做红头/红色分隔线/版式排版、不导出任何文件（仅输出 Markdown 校验/提取/校正结果）。
3. **不编造**：发文字号、签发人姓名、机关名称、日期等需据实填写的内容，AI 不得捏造。
4. **不联网**：本 Skill 全程本地处理，不调用任何外部 API 或模型。
5. **不处理敏感内容**：如公文涉密或含个人隐私（姓名/身份证/手机号），提醒用户脱敏后再处理，AI 不存储不外传。
6. **不绕过规范**：即使公文中存在"惯例"，仍以国标 GB/T 9704—2012 为准绳给出建议。
