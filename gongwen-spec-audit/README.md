# 公文辅助校验助手

> **丢一份已有公文进来，自动核查格式合不合规、提取关键信息、校正不规范术语。依据《党政机关公文格式》GB/T 9704—2012。仅做辅助校验，不起草公文、不生成版式文件。**

---

## 核心功能

- **格式校验**：逐项核查发文字号（六角括号〔〕）、成文日期、层次序号、主送机关、抄送、上行文签发人等 10+ 项，按 🔴严重/🟡提醒 分级，每条带标准条款和修改示例。
- **关键信息提取**：从来文一键抽取发文字号、发文机关、成文日期、金额数据、时限，可直接贴进收文登记台账。
- **术语校正**：40+ 条不规范用语 → 规范改法（请示报告混用、搞好、兹有、公分等），每条带依据。

> 本工具仅对**已有公文做辅助校验**，不具备公文起草、红头版式生成、Word/PDF 导出能力。

---

## 适用人群

- **机关文秘 / 办公室科员**：收发文核稿、上报前自查、批改下级来文。
- **政务外包 / 国企办公室**：批量核查公文格式、提取来文要素。
- **任何要检查党政公文格式的人**：不确定格式对不对时，丢进来校验。

---

## 使用流程

1. **给公文**：粘贴文本，或给 `.txt` 文件路径（PDF/Word 先转纯文本）。
2. **说要做什么**：校验格式 / 提取信息 / 校正术语。
3. **拿结果**：校验出问题清单，提取出要素表，术语出校正建议（均为 Markdown）。

---

## 使用示例

### ① 格式校验（输入一份含错的公文 → 输出问题清单）

**输入**（含 3 处典型错误的公文片段）：

```
×政办发[2026]12号              ← 发文字号用了方括号,应为六角括号〔〕
…
　　1、强化责任落实             ← 第一层序号应为「一、」
…
　　二〇二六年三月十日          ← 成文日期应为阿拉伯数字
```

**输出**（自动检出，每条带标准依据）：

| 级别 | 位置 | 问题 | 标准依据 |
|------|------|------|----------|
| 🔴严重 | 行3 | 发文字号年份未用六角括号〔〕：「政办发[2026]12号」 | GB/T 9704—2012 7.2.5 |
| 🔴严重 | 行13 | 正文层次序号出现「1、」（应为「一、」） | GB/T 9704—2012 7.3.3 |
| 🔴严重 | 行26 | 成文日期使用了中文数字：「二〇二六年三月」 | GB/T 9704—2012 7.3.5.4 |

### ② 关键信息提取（输入真实来文 → 输出要素表）

**输入**：一份政府办公厅的印发通知（PDF 抽取文本）

**输出**：

| 要素 | 内容 |
|------|------|
| 发文字号 | 武政办〔2025〕115号 |
| 发文机关 | 武汉市人民政府办公厅 |
| 成文日期 | 2025年12月22日 |
| 关键数据 | 10项、3人、1次 |

## 快速开始

对 AI 说一句话即可触发：

- "校验一下这份公文格式对不对"
- "提取这份来文的发文字号和关键信息"
- "校正这份公文的术语"

或直接跑脚本（纯标准库，零依赖，开箱即用）：

```bash
python scripts/gongwen_toolkit.py check 公文.txt       # 格式校验
python scripts/gongwen_toolkit.py extract 来文.txt      # 信息提取
python scripts/gongwen_toolkit.py glossary 公文.txt     # 术语校正
```

## 数据说明

- 校验规则严格对标 GB/T 9704—2012，每条问题标注标准条款，可溯源。
- 发文字号、签发人姓名、成文日期等需据实填写的内容，**不编造**。
- 全程本地处理，不联网、不调外部模型、不上传数据。
- 涉密或含个人隐私（姓名/身份证/手机号）的公文，请脱敏后再处理。
