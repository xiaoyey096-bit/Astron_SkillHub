# 简历-岗位智能匹配与差距诊断助手（resume-job-match）

> 中文技能名：**人岗匹配助手**
> 定位：把「一份简历 + 一份 JD」变成「一份量化的匹配度评分 + 逐条差距清单 + 可执行建议」。支持求职者自检（我差在哪、怎么补）和企业筛选（这份简历够不够、要不要面）。不联网、不调外部模型、本地处理。

本文件是 AI 调用入口。当用户触发以下任一场景时应加载本 Skill，并按下面的标准工作流程（SOP）执行。

> **能力边界（重要）**：本 Skill 只做**对用户已提供的简历与 JD 文本进行结构化解析、匹配评分与差距诊断**。**不具备**：联网抓取招聘网站 JD/简历、对接企业 ATS 系统、做背景调查/学历验证、自动投递、生成完整新简历（只给优化方向建议）。

---

## 一、核心原则（不可违反）

1. **硬性条件一票否决**：JD 明确标注的硬性要求（如"本科及以上""必须 3 年以上 Java""持有 CPA 证书"）若简历完全不满足，无论其他项多强，匹配度直接判「不通过」，并在差距清单置顶标红。避免"加权后总分还行"的假象。
2. **只基于提供的文本**：简历/JD 里没写的信息，不得臆测。简历没写学历不能默认本科，JD 没写薪资不能瞎编。无法判断的字段标「未提及」。
3. **解析交给脚本，匹配交给 AI**：简历/JD 的**结构化要素抽取**（联系方式正则、技能词库匹配、年限数字提取）调用 `scripts/match.py` 完成，保证可复现；**语义级匹配判断**（项目经历是否覆盖 JD 要求的能力、工作内容相关性）由 AI 基于抽取结果产出。
4. **客观中立**：匹配度基于真实要素比对，不为讨好求职者虚高评分，也不为讨好企业恶意压分。每条差距都给出依据。
5. **可执行**：差距清单不能只说"缺 X"，必须给出「怎么补」（求职者视角）或「是否可放宽」（企业视角）。

## 二、何时加载本 Skill（触发与边界）

当用户请求命中下面**任一**场景时加载：

| 场景关键词 | 对应能力 |
|-----------|---------|
| "匹配/匹配度/适不适合"简历与岗位 | 双向匹配 + 评分 |
| "差距/差在哪/够格吗/符合吗" | 差距诊断 + 建议 |
| "筛简历/排序/哪份更好"（HR/猎头，1 JD 多简历） | 批量评分排序 |

- 用户只要"帮我写/改一份新简历" → 本 Skill **不做简历生成**，只给优化方向；
- 用户只要"帮我写 JD" → 本 Skill **不做 JD 生成**；
- 用户给的是非简历非 JD 的普通文本 → 不加载。

## 三、标准工作流程（SOP）

### 第 1 步：接收并解析简历 + JD

**输入形式**（任一）：
- 简历：粘贴文本、`.txt`/`.md`/`.docx`（`.docx` 由脚本读取，依赖 `python-docx`，未安装则提示粘贴文本）；
- JD：粘贴文本或文件路径。

**解析动作**（调用 `python scripts/match.py parse <简历路径>` 与 `parse-jd <JD路径>`）：
- **简历要素抽取**：基本信息（姓名/手机/邮箱——手机邮箱做 PII 脱敏后展示）、教育（学校/学历/专业/时间段）、工作经历（公司/职位/时间段/工作年限累计）、技能（按 `references/skill-thesaurus.md` 词库匹配）、项目经历（项目名/角色/技术栈/时长）、证书。
- **JD 要素抽取**：岗位名、硬性要求（学历/年限/必备技能/证书/行业）与加分项（优先技能/软性要求）、职责描述、（若有）薪资范围。

**歧义确认闸**（一次性反问）：
- 简历工作时间跨段重叠或断档 → 询问如何计算累计年限；
- JD 某条要求是"硬性"还是"加分"不明确（如"熟悉 Python 优先"）→ 询问归类；
- 多岗位 JD 混在一起 → 询问以哪个岗位为主。

### 第 2 步：双向匹配 + 匹配度评分

调用 `python scripts/match.py score <简历路径> <JD路径>` 得到机器可判定的部分（技能词库命中、年限数值比对、学历比对、证书比对），AI 在此基础上补语义匹配（项目经历覆盖度、工作内容相关性）。

**评分模型**（透明、可解释）：
1. **硬性条件检查**（一票否决）：逐条比对 JD 硬性要求 vs 简历。任一硬性完全不满足 → `硬性通过=False`，匹配度封顶标「不通过」。
2. **加权打分**（硬性全过或部分过时计算）：
   - 学历匹配（权重 15%）：达标 100%，超出 100%，低于 0%；
   - 年限匹配（20%）：达标 100%，每少 1 年扣 20%（最多扣完）；
   - 核心技能覆盖（35%）：必备技能命中率 × 100%；
   - 项目/经历相关性（20%）：AI 语义判断 0-100%；
   - 加分项（10%）：加分技能/证书命中比例。
3. **综合匹配度** = 各项 × 权重之和，四舍五入到整数百分比。
4. **定性结论**：≥85%「高度匹配」/ 70-84%「较匹配」/ 55-69%「部分匹配」/ <55%「匹配度低」；硬性不通过时无论分数标「不通过（硬性条件未满足）」。

### 第 3 步：差距诊断清单

按 JD 要求逐条输出比对结果，分四类：
- ✅ **命中**：简历明确满足（附依据，如"工作年限 5 年 ≥ 要求 3 年"）；
- 🟡 **部分满足**：接近但不完全（如"会 Python 但 JD 要 3 年经验，简历体现 1 年"）；
- 🔴 **缺失**：简历完全未体现（标红 + 置顶，若是硬性要求）；
- ⚪ **未提及**：简历/JD 信息不足无法判断（不臆测）。

### 第 4 步：可执行建议

- **求职者视角**（默认，若用户是 HR 则切换企业视角）：针对每条 🔴🟡 给出补强方向（如"补一个 Python 数据处理项目""证书可在 X 方向考取"），并指出简历里**已有但未体现好**的亮点（埋没的经历可重写突出）。
- **企业视角**（HR/猎头）：指出哪些硬性要求可能是"不必要的门槛"导致漏掉合适人选，建议放宽或改为加分项。

### 第 5 步：输出匹配报告

按 `templates/match-report-template.md` 输出，结构固定：
1. 总览（匹配度评分 + 定性结论 + 硬性是否通过）；
2. 评分明细表（各维度得分与权重）；
3. 差距诊断清单（逐条 ✅🟡🔴⚪）；
4. 优化建议（求职者/企业视角）；
5. 隐私与局限说明。

**批量模式**（1 JD 多简历）：输出排序表（按匹配度降序），每份简历给一行总览 + 是否建议进入面试，详细报告按需展开。默认在对话区呈现 Markdown，用户要求导出时输出经 sanitize 的 CSV（如筛选排序表）。

## 四、输入输出约定

- **输入**：简历 + JD（文件路径或粘贴文本）。
- **输出**：Markdown 匹配报告；表格动态字段经 `sanitize_cell()`；简历中的手机号/邮箱/身份证在展示时脱敏（如 `138****1234`）。
- **语言**：中文，结论直白，评分依据可追溯。

## 五、异常与边界情况处理清单（鲁棒性保障）

| 异常情况 | 处理方式 |
|---------|---------|
| 简历或 JD 为空 | 报告"输入不足"，不强行匹配 |
| 简历无工作经历（应届生） | 年限维度按 0 处理，若 JD 要求经验则触发硬性否决并提示 |
| JD 未区分硬性与加分 | 经歧义确认闸，默认把"必须/要求/需"归硬性，"优先/加分/熟悉"归加分 |
| 简历技能表述与词库不一致（如"py"/"Python3"） | 按 `references/skill-thesaurus.md` 同义词归一后匹配 |
| 简历含多个学历/多段经历 | 取最高学历、累计工作年限，项目经历全部保留 |
| JD 含模糊要求（如"良好的沟通能力"） | 归软性加分项，不纳入硬性否决，AI 从简历自述/项目角色侧面判断 |
| 简历为扫描图片 | 提示用户先转文本（本 Skill 不做 OCR） |
| `.docx` 依赖 python-docx 未安装 | 提示粘贴文本，不报错中断 |
| 用户要求"帮我改简历/写简历" | 告知不做生成，仅基于差距清单给优化方向 |
| 用户要求"帮我看薪资合不合理" | 若 JD 有薪资范围则客观呈现，不做行业薪酬调查（不联网） |
| 简历含 PII（手机/邮箱/身份证） | 展示时脱敏，不存储不外传 |
| 文本含特殊字符/公式前缀 | sanitize_cell 净化 |

## 六、结果验收标准

- 对 `samples/简历-后端开发.txt` + `samples/JD-Java后端.txt`：应正确抽取双方要素；硬性条件（本科/3年/Java/Spring）逐条比对；输出匹配度评分与定性结论一致；差距清单至少含 1 条 ✅ 与 1 条 🔴 或 🟡；给出 ≥2 条可执行建议。
- 对一份明显不匹配的简历（如纯前端投 Java 后端 JD）：应判硬性不通过或匹配度低，并置顶标红缺失的核心技能。
- PII 脱敏：手机号展示为 `138****1234` 形式。

测试命令：`python tests/run_test.py`。

## 七、不应该做什么（边界与合规）

1. **不联网**：不抓招聘网站、不查薪酬数据库、不做背调，全程本地处理用户提供的文本。
2. **不生成简历/JD**：只做匹配诊断与优化方向建议，不替用户写新简历或新 JD。
3. **不编造信息**：简历/JD 没写的字段标「未提及」，不默认、不臆测。
4. **不虚高/压分**：评分基于要素比对，每分都有依据。
5. **不存储外传 PII**：简历含个人信息时脱敏展示，提醒用户注意隐私。
6. **不下死结论**：匹配度是参考，最终是否录用/投递由人决定，报告中明示「AI 辅助参考」。

## 八、文件说明

- `references/skill-thesaurus.md`：技能同义词词库（"py/Python3/Python" 归一），供脚本匹配用。
- `templates/match-report-template.md`：匹配报告固定输出模板。
- `samples/`：测试样例（简历、JD）。
- `scripts/match.py`：匹配脚本，子命令 `parse`/`parse-jd`/`score`，纯标准库 + 可选 python-docx，内置 `sanitize_cell()` 与 PII 脱敏。
- `tests/run_test.py`：一键自测。
- `README.md`：完整使用说明。
