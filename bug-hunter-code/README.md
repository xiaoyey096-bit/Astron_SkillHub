# 代码缺陷定位与质量审查助手（bug-hunter-code）

> **贴一段代码进来，自动扫出安全漏洞、潜在 Bug 和规范问题——每条都给位置、风险等级、修复建议和可直接抄的修复示例。提交/合并前自查、Code Review 辅助都好用。**

---

## 核心功能

- **安全漏洞扫描**：命令注入、SQL 注入、硬编码密钥、路径穿越、不安全反序列化、SSL 校验禁用——高危项优先报，每条标 🔴严重。
- **缺陷与坏味道**：资源未释放、异常被静默吞没、裸 except、超长函数、高圈复杂度、遗留 TODO。
- **每条可执行**：位置（行号 + 代码片段）+ 风险说明 + 修复方向 + **可直接抄的修复示例代码**，不只说"这里有风险"。
- **静态规则 + AI 语义双轨**：可模式化的问题由脚本确定性扫描（可复现、不漏报）；逻辑错误、命名等语义问题由 AI 基于上下文判断。

---

## 适用人群

- **开发者**：提交/合并前自查，提前扫掉低级安全和缺陷问题，省下 Review 往返。
- **Reviewer / 技术负责人**：Code Review 辅助，快速定位高危项，聚焦真正需要人判断的地方。
- **新人 / 转语言者**：把关代码质量，从修复示例里学到正确写法。

---

## 使用流程

1. **提供代码**：上传代码文件（`.py`/`.js`/`.ts`/`.java` 等）或直接粘贴代码。
2. **自动识别**：按扩展名/特征识别语言，超长代码提示分段。
3. **生成报告**：输出审查总览 + 分级问题清单（🔴严重/🟡警告/🟢建议）+ 整体评价。需要导出问题清单为 CSV 说一声。

---

## 使用示例

**输入**（一段含问题的 Python 代码）：

```python
def query_orders(user_id, keyword):
    cur.execute("SELECT * FROM orders WHERE id = %s AND name LIKE '%%%s%%'" % (user_id, keyword))

def run_report(cmd):
    os.system("generate-report " + cmd)
```

**输出**（自动生成，节选）：

> **🔴 严重 · sql-concat（第 2 行）**：SQL 字符串用 `%` 拼接变量，存在 SQL 注入风险。
> 修复：`cur.execute("... WHERE id = ? AND name LIKE ?", (user_id, f"%{keyword}%"))`
>
> **🔴 严重 · os-system（第 5 行）**：`os.system` 拼接 `cmd`，存在命令注入（RCE）风险。
> 修复：`subprocess.run(["generate-report", cmd], shell=False)`
>
> **优先修复 Top**：先修 2 处 🔴 安全漏洞，再处理异常处理类 🟡。

## 安全说明

- **不执行你的代码**：全程静态分析，绝不 import/运行你提供的代码（避免安全风险）。
- **不联网**：规则库本地内置，不查在线接口、不调外部模型、不上传你的代码。
- **不编造问题**：规则没命中、语义无问题的，会如实报告"未发现严重问题"。

---

## 能力边界

本助手**只做**对已提供代码的静态审查与修复建议。**不做**：联网拉取仓库、对接 CI/CD、执行代码做动态测试、自动提交修复、性能基准测试。
