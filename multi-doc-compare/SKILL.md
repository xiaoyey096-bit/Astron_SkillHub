# 多文档对比与差异洞察助手（multi-doc-compare）

> 中文技能名：**多文档对比助手**
> 定位：把「多份同主题但散乱的文档」变成「一张对比矩阵 + 共识/分歧/独有信息的差异洞察」。纯本地运行、不联网、不调外部模型。

本文件是 AI 调用入口。当用户触发以下任一场景时应加载本 Skill，并按下面的标准工作流程（SOP）执行。

> **能力边界（重要）**：本 Skill 只做**对用户已提供的多份文档进行维度对齐、内容比对与差异洞察**。**不具备**：联网检索外部文档、自动抓取网页资料、判断文档真伪、给出绝对正确的结论（只做基于所提供文档的客观比对）。

---

## 一、核心原则（不可违反）

1. **忠于原文、客观比对**：对比矩阵里的每个单元格内容都必须来自对应文档原文，不脑补、不合并不同文档的信息。A 文档没写的就标「未提及」，不能拿 B 的内容填给 A。
2. **区分事实与判断**：客观呈现各文档"说了什么"，区分"共识"（多份一致）和"分歧"（互相矛盾），不替用户判定谁对谁错。
3. **维度对齐交给脚本，洞察交给 AI**：维度提取、关键词命中统计、文档结构解析这类**模式化处理**调用 `scripts/doc_compare.py`；维度归类、共识/分歧判断、洞察提炼由 AI 完成。
4. **不偏袒任何一方**：多文档对比中立呈现，不预设某份文档更权威。
5. **缺失内容如实标注**：某文档没覆盖某维度的，标「未提及」，不臆测。

---

## 二、何时加载本 Skill（触发与边界）

当用户请求命中下面**任一**场景时加载：

| 场景关键词 | 对应能力 |
|-----------|---------|
| "对比/横向对比/选型"多份文档/方案/产品 | 对比矩阵 + 差异洞察 |
| "找异同/共识/分歧/交叉验证" | 共识/分歧识别 |
| "汇总/整合"多篇资料 | 多源信息整合（标注来源） |

**不应加载**的情况：
- 只有一份文档要"总结" → 这是单文档摘要，本 Skill 面向多文档对比，至少 2 份；
- 用户要"联网查几篇再对比" → 本 Skill **不联网**，需用户先提供文档；
- 用户要"判断哪个对" → 本 Skill **不下真假结论**，只客观呈现分歧。

## 三、标准工作流程（SOP）

### 第 1 步：接收并解析多份文档

**输入形式**：
- 多份文档：每份用分隔符（如 `===文档1===`）或分别提供文件路径；
- 每份文档可以是文本、表格、Markdown。

**解析动作**（调用 `python scripts/doc_compare.py parse <文件>`）：
- 按分隔符切分多份文档；
- 对每份文档提取：标题/主题、关键词、覆盖的维度（按 `references/dimension-extract.md` 的通用维度库 + 文档自带的小标题）。

### 第 2 步：维度对齐与对比矩阵

调用 `python scripts/doc_compare.py matrix <文件>`：
- 汇总所有文档涉及的可对比维度（取并集）；
- 生成对比矩阵：行=维度，列=各文档，单元格=该文档在该维度的内容（无则「未提及」）。

AI 在此基础上：
- **维度归类**：把零散的关键词归并成有意义的对比维度（如"价格""功能""优缺点"）；
- **统一口径**：不同文档对同一维度的不同表述，归到同一行（如"售价"和"价格"合并）。

### 第 3 步：共识 / 分歧 / 独有信息识别

调用 `python scripts/doc_compare.py diff <文件>` 得到关键词层面的命中差异，AI 做语义层判断：
- **共识点**：多份文档都提到且一致的内容（如 3 份产品资料都说支持导出 PDF）；
- **分歧点**：对同一维度互相矛盾的内容（如 A 说免费、B 说收费），客观呈现双方表述；
- **各自独有信息**：只有某一份文档提到的特色/信息。

### 第 4 步：输出对比报告

按 `templates/compare-report-template.md` 输出，结构固定：
1. 对比概览（文档清单、对比维度数）；
2. 对比矩阵（核心，行=维度、列=文档）；
3. 共识点；
4. 分歧点（含各文档表述）；
5. 各自独有信息；
6. 差异洞察（AI 归纳：这些差异说明什么、选型/决策可参考的角度）；
7. 局限说明（仅基于所提供文档）。

默认在对话区呈现 Markdown。用户要求导出时输出经 sanitize 的 CSV（对比矩阵）。

---

## 四、输入输出约定

- **输入**：≥2 份同主题文档（文本/表格/文件，用分隔符或分别提供）。
- **输出**：Markdown 对比报告；表格经 `sanitize_cell()`；保留各文档原文表述。
- **语言**：中文，客观中立。

---

## 五、异常与边界情况处理清单（鲁棒性保障）

| 异常情况 | 处理方式 |
|---------|---------|
| 仅 1 份文档 | 提示"对比至少需要 2 份文档" |
| 文档主题完全不同 | 提示"这些文档主题差异大，可对比维度少"，仍尽力找交集 |
| 文档维度对不上 | 客观呈现，无法对齐的标"维度不对应" |
| 某文档极短/信息少 | 该文档列大量「未提及」，提示信息量有限 |
| 分歧无法判定对错 | 客观呈现双方表述，标"需进一步核实" |
| 文档含矛盾数据 | 标为分歧点，提示"各文档数据不一致" |
| 文档数量多（>5份） | 提示取关键维度对比，避免矩阵过宽 |
| 用户问"哪个最好" | 客观呈现差异，不给"最好"结论（除非有明确评价标准） |
| 文本含特殊字符 | sanitize_cell 净化 |

## 六、结果验收标准

- 对 `samples/产品对比样例.txt`（3份产品资料，含共识/分歧/独有信息）：应生成对比矩阵（≥4个维度）、识别≥2个共识点、≥1个分歧点、标出各自独有信息、客观不偏袒。
- 对比矩阵单元格：未覆盖的维度标「未提及」，不脑补。
- 不出现"X产品最好""Y是对的"等主观结论。

测试命令：`python tests/run_test.py`。

---

## 七、不应该做什么（边界与合规）

1. **不联网**：不抓网页、不查外部资料、不调外部模型。
2. **不脑补**：矩阵单元格只填文档原文有的内容，没有的标「未提及」。
3. **不下真假结论**：分歧点客观呈现，不判谁对谁错。
4. **不偏袒**：多文档中立比对。
5. **不替用户决策**：呈现差异供参考，不直接说"选哪个"（除非用户给了明确标准）。
6. **不混淆来源**：每条信息标注来自哪份文档。
