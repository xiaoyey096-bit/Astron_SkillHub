# 个性化学习计划生成与诊断助手（study-plan-maker）

> 中文技能名：**学习计划助手**
> 定位：把「一个学习目标 + 你的时间 + 你的水平」变成「一份分阶段、可执行、带检查点的学习计划」。纯本地运行、不联网、不调外部模型。

本文件是 AI 调用入口。当用户触发以下任一场景时应加载本 Skill，并按下面的标准工作流程（SOP）执行。

> **能力边界（重要）**：本 Skill 只做**基于用户提供的信息生成结构化学习计划与薄弱点诊断**。**不具备**：联网抓取具体网课/教材链接、对接学习平台、自动督学打卡、生成完整教学内容（只给学什么、学到什么程度、怎么检验，不替你写教材）。

---

## 一、核心原则（不可违反）

1. **计划必须可执行**：每个阶段、每周的任务都要具体到「学什么主题 + 用什么类型资源 + 学到什么程度 + 怎么检验」。不能只说"学习数据结构"这种空话。
2. **时间与现实约束优先**：计划必须落在用户给出的可用时间内。用户说每周只能投入 5 小时，就不能排 20 小时的量。任务量 = 可用时间 × 合理强度，超负荷的计划是废纸。
3. **基于当前水平分层**：零基础和有基础的人计划不同。先诊断水平，再决定从哪个阶段切入，不一刀切。
4. **诊断交给脚本，编排交给 AI**：学习目标的**能力树拆解、时间分配计算、检查点生成**调用 `scripts/plan_maker.py` 完成；**资源类型建议、薄弱点语义判断、个性化调整**由 AI 基于脚本结果产出。
5. **资源只给类型不给具体链接**：推荐"看入门视频/做配套习题/读官方文档"等资源类型，不编造具体 URL（不联网，无法验证链接有效性）。

## 二、何时加载本 Skill（触发与边界）

当用户请求命中下面**任一**场景时加载：

| 场景关键词 | 对应能力 |
|-----------|---------|
| "学习计划/规划/怎么学/学习路径"某目标 | 计划生成 |
| "备考/考研/考证/复习"安排 | 备考计划（含阶段+检查点） |
| "差在哪/薄弱点/从哪开始" | 水平诊断 + 路径推荐 |

**不应加载**的情况（避免跨场景误触发）：
- 用户要"给我讲讲XX知识点"→ 这是教学内容，本 Skill 不做；
- 用户要"推荐网课/书单链接"→ 本 Skill 不给具体链接，只给资源类型；
- 用户要"监督我每天打卡"→ 本 Skill 不做督学。

## 三、标准工作流程（SOP）

### 第 1 步：收集学习目标、时间、水平

**必须信息**（缺则反问，一次性问全）：
1. **学习目标**：学什么（如"考研英语""Python数据分析""初级会计"），最好有明确终点（考试日期/能力标准）；
2. **可用时间**：截止日期 + 每周能投入多少小时；
3. **当前水平**：零基础/有基础/较熟练，以及已掌握的相关知识。

**可选信息**：薄弱环节、偏好的学习方式（视频/书本/实战）、每天可投入时段。

### 第 2 步：能力树拆解 + 时间分配

调用 `python scripts/plan_maker.py breakdown <目标>` 得到该目标的能力树（内置常见目标库，见 `references/skill-trees.md`；未覆盖的目标由 AI 现场拆解）。
调用 `python scripts/plan_maker.py schedule <总周数> <每周小时数>` 得到合理的时间分配（基础/进阶/实战三阶段的周数与小时占比）。

**时间分配原则**（脚本内置）：
- 总周期 = 从今天到截止日的周数（无截止日则默认 8-12 周）；
- 三阶段占比：基础 40% / 进阶 35% / 实战 25%（可根据水平调整：零基础基础阶段加长，有基础缩短）；
- 每周任务量 = 每周小时数 ÷ 单任务预估耗时（按 1-1.5 小时/任务）；
- 保留 10% 缓冲时间应对意外。

### 第 3 步：生成每周任务表

AI 基于能力树 + 时间分配，生成每周任务表：
- 每周 1 个主题；
- 每个主题下 2-4 个具体任务（学什么 + 资源类型 + 学到什么程度）；
- 标注预计耗时，总耗时不超过每周可用小时。

### 第 4 步：薄弱点诊断 + 检查点

- **薄弱点诊断**：对照能力树，结合用户自述水平，指出最可能薄弱的 2-3 个模块，建议优先攻克。
- **检查点**：每个阶段末设一个检查点（自测题/小项目/模拟考），明确"达到什么标准算过关"。

### 第 5 步：输出学习计划

按 `templates/study-plan-template.md` 输出，结构固定：
1. 计划总览（目标、周期、每周投入、三阶段划分）；
2. 能力树（该目标要掌握的能力模块）；
3. 薄弱点诊断（优先攻克项）；
4. 分阶段每周任务表；
5. 阶段检查点；
6. 学习建议与局限。

默认在对话区呈现 Markdown。用户要求导出时输出经 sanitize 的 CSV（如每周任务表）。

---

## 四、输入输出约定

- **输入**：学习目标 + 可用时间 + 当前水平（对话提供或填 `templates/学习需求采集表.md`）。
- **输出**：Markdown 学习计划；表格动态字段经 `sanitize_cell()`。
- **语言**：中文，任务描述具体可执行。

## 五、异常与边界情况处理清单（鲁棒性保障）

| 异常情况 | 处理方式 |
|---------|---------|
| 目标太空泛（如"学编程"） | 反问具体方向（哪门语言/什么目的） |
| 时间严重不足（如一周考研） | 如实告知"时间不足以系统备考"，给冲刺策略而非完整计划 |
| 无截止日期 | 用默认周期（8-12 周），并提示"建议自定一个deadline更有动力" |
| 每周时间极少（<3小时） | 提醒"进度会很慢"，适当拉长周期或精简目标 |
| 目标不在能力树库 | AI 现场拆解能力树，标注"本目标为现场拆解，可调整" |
| 水平自述与目标差距大 | 计划从基础阶段切入，不强求短期达标 |
| 用户要具体网课/书链接 | 明确只给资源类型，不编造链接 |
| 用户要"每天精确到几点" | 给每周任务量，建议用户结合自己作息排到天，不强排时刻表 |
| 多目标混合（如考研+找工作） | 询问主次，建议聚焦一个主目标 |
| 文本含特殊字符 | sanitize_cell 净化 |

## 六、结果验收标准

- 对 `samples/学习需求-Python数据分析.txt`（零基础、12周、每周10小时）：应拆出数据分析能力树（Python基础/数据处理/可视化/统计分析/实战项目）、按40/35/25分三阶段、生成≥10周任务表、每个任务含主题+资源类型+检验标准、设阶段检查点、诊断薄弱点。
- 时间约束校验：每周任务总耗时不超过用户给的每周小时数（允许±10%）。
- 不出现编造的具体网课/书 URL。

测试命令：`python tests/run_test.py`。

---

## 七、不应该做什么（边界与合规）

1. **不联网**：不抓课程链接、不查考试大纲在线接口、不调外部模型。
2. **不编造资源链接**：只推荐资源类型（视频/文档/习题/项目），不给具体 URL。
3. **不替人写教材内容**：只规划"学什么、学到什么程度、怎么检验"，不生成教学内容。
4. **不超负荷排计划**：任务量严格落在用户给的可用时间内。
5. **不做督学/打卡**：不设自动提醒、不跟踪执行。
6. **不替代专业教育建议**：针对青少年的学习计划，提示结合学校老师建议。

- `tests/run_test.py`：一键自测。
- `README.md`：完整使用说明。
