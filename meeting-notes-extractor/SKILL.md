# 会议纪要智能生成助手（meeting-notes-extractor）

> 中文技能名：**会议纪要助手**
> 定位：把「一段会议录音转写文本或会议记录」变成「一份结构清晰、有待办跟进的会议纪要」。纯本地运行、不联网、不调外部模型。

本文件是 AI 调用入口。当用户触发以下任一场景时应加载本 Skill，并按下面的标准工作流程（SOP）执行。

> **能力边界（重要）**：本 Skill 只做**对用户已提供的会议文本进行结构化提炼与纪要生成**。**不具备**：录音转写（需用户先提供转写文本）、实时会议记录、对接会议系统/日历、自动催办待办。

---

## 一、核心原则（不可违反）

1. **忠于原文、不编造**：纪要里的每条决议、待办、要点都必须来自用户提供的会议文本。没讨论的内容不能写进纪要，模糊的不能脑补成确定结论。
2. **待办必含三要素**：提取的每个待办事项（action item）必须尽量包含「事项 + 责任人 + 截止日期」三要素。缺责任人的标「⚠️待确认责任人」，缺截止的标「⏳未定截止」。这是会议纪要最有价值的部分，必须可跟进。
3. **区分事实与意向**：明确区分「已决定的决议」和「讨论中提到的想法/倾向」。把想法写成决议是严重错误。
4. **抽取交给脚本，提炼交给 AI**：发言人识别、时间/日期识别、待办关键词命中这类**模式化抽取**调用 `scripts/notes_gen.py`；议题归类、要点凝练、决议判断这类**语义提炼**由 AI 完成。
5. **保密意识**：会议内容可能涉密，全程本地处理，不存储不外传。

---

## 二、何时加载本 Skill（触发与边界）

当用户请求命中下面**任一**场景时加载：

| 场景关键词 | 对应能力 |
|-----------|---------|
| "纪要/记录/整理/总结"一场会议 | 全流程纪要生成 |
| "待办/action items/决议/要点" | 专项提取 |
| "同步给未参会同事" | 纪要 + 背景说明 |

**不应加载**的情况（避免跨场景误触发）：
- 用户只有录音文件要"转写" → 本 Skill **不做录音转写**，需用户先用讯飞听见等工具转成文本；
- 用户要"实时记录正在开的会" → 本 Skill 处理已有文本，不做实时；
- 用户要"帮我把纪要发到群里/录入系统" → 本 Skill 不对接外部系统。

## 三、标准工作流程（SOP）

### 第 1 步：接收并解析会议文本

**输入形式**（任一）：
- 会议录音转写文本（含发言人标签，如「张三：...」「A: ...」或纯文本无发言人）；
- 手写的会议记录/要点；
- 文件路径（`.txt`/`.md`）。

**解析动作**（调用 `python scripts/notes_gen.py parse <文件>`）：
- 识别发言人（按「姓名：」「A:」等模式切分），统计发言次数；
- 识别文本中的时间/日期表达（"下周三""7月15日""月底前"等）；
- 识别待办关键词（"需要""负责""跟进""安排"" deadline""确认""提交"等）。

### 第 2 步：要素提取（脚本 + AI）

调用 `python scripts/notes_gen.py extract <文件>`，机器抽取：
- **待办候选**：含待办关键词 + 责任人（人名/角色）+ 截止的句子；
- **时间表达**：所有出现的日期/时间；
- **发言人清单**。

AI 在此基础上做语义提炼：
- **议题**：本次会议讨论了哪几个主题（归类，3-5个）；
- **讨论要点**：每个议题下的关键观点（中立概括，不偏不倚）；
- **决议**：明确达成的结论（区分"决定"vs"建议/倾向"）；
- **遗留问题/风险**：悬而未决、有分歧、需进一步确认的事项。

### 第 3 步：生成会议纪要

按 `templates/meeting-notes-template.md` 输出，结构固定：
1. 会议信息（主题/时间/参会人，若文本有则填，无则标"未提及"）；
2. 议题与讨论要点；
3. 决议（明确结论）；
4. 待办事项表（事项+责任人+截止，最重要的部分）；
5. 遗留问题与风险；
6. 按发言人归集观点（可选，若文本有发言人标签）。

### 第 4 步：待办校验与提示

- 待办表里缺责任人/截止的，明确标注提示用户补全；
- 若整场会议无任何明确待办，提示"本次会议为讨论/同步性质，无具体待办"；
- 若待办过多（>10条），建议按优先级分组。

默认在对话区呈现 Markdown。用户要求导出时输出经 sanitize 的 CSV（如待办清单）。

---

## 四、输入输出约定

- **输入**：会议转写文本或会议记录（文件路径或粘贴文本）。
- **输出**：Markdown 会议纪要；表格动态字段经 `sanitize_cell()`；人名/专有名词保留原文。
- **语言**：中文为主，英文术语保留。

---

## 五、异常与边界情况处理清单（鲁棒性保障）

| 异常情况 | 处理方式 |
|---------|---------|
| 文本为空或极短 | 报告"内容不足，无法生成纪要" |
| 无发言人标签（纯文本） | 跳过按发言人归集，按议题组织 |
| 无明确决议 | 如实写"本次为讨论会，未形成明确决议"，列出各方倾向 |
| 待办无责任人 | 标⚠️待确认，提示用户补 |
| 待办无截止 | 标⏳未定截止 |
| 责任人是"大家/我们" | 提示需明确到具体人 |
| 时间表达模糊（"尽快""近期"） | 原样保留并标"需明确具体日期" |
| 多个会议混在一起 | 询问是否分别生成 |
| 会议很长（转写上万字） | 提示聚焦关键部分或分段，纪要控制在合理长度 |
| 文本含人名等敏感信息 | 提醒保密，本地处理不外传 |
| 技术术语/项目代号多 | 保留原文，必要时加备注 |
| 文本含特殊字符 | sanitize_cell 净化 |

## 六、结果验收标准

- 对 `samples/会议转写-产品评审.txt`（含3个发言人、2个议题、决议、带责任人和截止的待办、1个遗留问题）：应正确识别发言人、提取≥3条待办（含三要素）、区分决议与讨论、标出遗留问题。
- 待办三要素：至少有2条待办同时含事项+责任人+截止。
- 不把讨论中的"可以考虑"写成决议。

测试命令：`python tests/run_test.py`。

---

## 七、不应该做什么（边界与合规）

1. **不录音转写**：只处理已有文本，不做语音转文字。
2. **不编造**：决议/待办/要点必须来自原文，没说的不写。
3. **不混淆事实与意向**：讨论想法≠决议。
4. **不对接外部系统**：不发群、不录日历、不自动催办。
5. **不存储外传**：会议内容本地处理，保密。
6. **不遗漏待办**：待办是纪要核心，宁可多提取供用户筛，不能漏。
